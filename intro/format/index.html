    格式手册

    本页维护 Physics Learning Wiki 的 Markdown、公式与资源排版规则．教学组织和术语以 内容编写指引 为准；按实际编辑任务查阅对应规则即可．

    如果您已迫不及待，想要快速上手，建议先阅读 太长不看版 与 图片举例 的章节．

    太长不看版

    为方便初次阅读本文档的用户，本节列举该手册中的若干重点事项：

    • 文件存储：

      • 使用小写文件名，以 - 代替空格．详见 SAVE-1．

      • 不要插入外链图片．详见 SAVE-2．

      • 图片尽可能使用 SVG 格式，只应使用 SVG 1.1 标准．详见 SAVE-3．

      • 动图应使用 SVG 或 APNG 格式．详见 SAVE-4．

      • 有源文件的图片建议同时提交源文件．详见 SAVE-5．

      • 插入外链时建议同时插入快照链接．详见 SAVE-6．

      • 不要以插入外链的方式插入内链．详见 SAVE-7．

    • 标点符号：

      • 规范使用标点符号．在每句话的末尾添加 句号．详见 PUNC-1 至 PUNC-7．

      • 注意区分连接号（hyphen、en dash、em dash）．详见 PUNC-8．

    • Markdown 语法与主题扩展语法：

      • 只应使用二级、三级、四级标题．不要使用标题替代加粗．不要在标题写 LaTeX 公式．详见 LINT-1、MDFM-1、CONT-4、CONT-9．

      • 使用折叠框6语法和选项卡7语法时，须保持内部缩进一致，对空行也是如此．不要漏掉 空行的空格缩进．详见 LINT-6、MDFM-6．

      • 不要使用删除线 ~~foo~~ 语法．详见 LINT-3．

      • 行间公式应写作

        而不是 $$a^{2}=b^{2}+c^{2}$$．详见 LINT-5．

      • 行内公式应该使用单个 $ 并且应当使用单个空格与周围内容隔开，写作 文字 $a^{2}=b^{2}+c^{2}$ 文字 而不是 文字$a^{2}=b^{2}+c^{2}$文字．详见 LINT-4.3．

      • 补充与答案使用信息框的条件见 MDFM-5，核心主线保持可见．

      • 代码块只应使用 ``` 语法，且须标注语言．详见 LINT-7、MDFM-3．

    • LaTeX 公式：

      • 不应与 数学符号表 相冲突．详见 MATH-1.1．

      • 注意字体的使用，详见 MATH-1.2、MATH-1.15、MATH-2.6、MATH-2.7．

      • 不要滥用 LaTeX 公式．详见 MATH-1.14．

      • 不要 LaTeX 公式里使用程序设计语言的表示方式．（如：不要使用 𝑎 ==𝑏a==ba==b、𝑎 <<1a<<1a<<1、𝑎%𝑏a%ba %b．）不要使用中括号连缀（𝑎[𝑖][𝑗]a[i][j]a[i][j]）．详见 MATH-1.9、MATH-1.10．

    • 代码：

      • 尽可能简洁易懂，避免压行，说明计算对象与方法．语法见 MDFM-3．

      • 代码示例使用带实际语言标记的围栏．详见 MDFM-3．

      • 不推荐在无关场合滥用计算机工具，应先介绍物理内容的概念及思想，而非直接进行计算．

    对本文档的格式要求

    • FREQ-1：修订格式手册的条目时需同时补充 Changelog．若只是修正格式，则无需补充 Changelog．
    • FREQ-2：除 太长不看版 一节外，格式手册的条目都需要有不重复的编号，编号需要匹配正则表达式 (?<category>[A-Z]{4})-(?<id>[1-9][0-9]*(?:\.[1-9][0-9]*)*)，其中 category 应具有直观的含义．说明文字不需要有编号．
    • FREQ-3：太长不看版 的条目必须来自格式手册其他章节的内容，且需在末尾引用对应的条目编号．
    • FREQ-4：条目的编号一旦确定就不应更改．如果确需更改（如删除、合并条目），则应用类似「已废止」、「迁移至 XXXX-id」的文字注明．

    贡献文档要求

    当你打算贡献某部分的内容时，你应该尽量熟悉以下三部分：

    • 文档存储的格式
    • 文档的合理性
    • remark-lint 和 LATEXLATEXLaTeX 公式的格式要求

    文档引用与存储的格式

    • SAVE-1：文件名请务必都小写，以 - 分割． 例如：file-name.md．

    • SAVE-2：请务必确保文档中引用的 外链 图片已经全部转存到了 本库内 对应的 images 文件夹中（防止触发某些网站的防盗链），建议处理成 MD 文档名称 + 编号 的形式（可参考已有文档中图片的处理方式）．例如：本篇文档的文件名称为 format，则文档中引用的第一张图片的名字为 format1.png．

    • SAVE-3：推荐使用 SVG 格式的图片1，以获取较好的清晰度和缩放效果．由于 Physics Learning Wiki 各组件对 SVG 标准的兼容性不同，所以您的图片应基于 SVG 1.1 标准．

    • SAVE-4：动图如果无法或者不会制作 SVG 格式的，则推荐使用 APNG 格式2的文件．Windows 用户可使用 ScreenToGif 录制，Linux 用户可使用 Peek 录制，注意需要在设置里调整为录制 APNG．其他情况则推荐先制作为 MP4 等视频文件再转换为 APNG，如果使用 ffmpeg 则可以使用 ffmpeg -i filename.mp4 -f apng filename.apng -plays 0 转换．3

    • SAVE-5：同时具有源文件和导出图像的图片（例如 JPG 文件与 PSD 文件或者 SVG 图像与 TikZ TeX 源代码），建议将源文件以与图片相同的文件名保存于同一目录下．

    • SAVE-6：请确保您的文档中的引用链接的稳定性．不推荐 引用 自建 服务中的资源（如缺少长期归档的个人题目页面）．建议在添加时同时将该外链存于互联网档案馆4，以防无法替代的链接失效．

    • SAVE-7：站内链接请去掉网站域名，并且使用相对路径链接对应 .md 文件．例如，在本页面（intro/format）中链接杂项简介（misc），应使用 [杂项简介](../misc/index.md)．可以在链接中添加 hash 来链接到某一节，例如 [Pull Request 信息格式规范](./htc.md#pull-request-信息格式规范)，hash 的值可以通过位于每个标题右侧的按钮或者位于网页右侧的目录中的链接得到．

    文档的合理性

    STRC-1：读者、任务与难度安排以 内容编写指引 为准．本手册负责格式，不重复规定教学结构．

    STRC-2：正文中的条件、推理与结论应能连续阅读；组织方式按页面任务选择．

    • STRC-2.1：概念、证明、导读和速查页承担不同任务，不要求相同的栏目或例题数量．取舍见 教学示例．
    • STRC-2.2：工具页说明输入、输出、适用条件和实际操作，下载与配置链接优先使用官方文档．

    修改已有文章先保留有效解释，再定位需要替换或合并的片段；追加说明时避免重复．审校与验证流程见 编辑审校．

    文档的基本格式要求

    Remark-lint 的格式要求

    remark-lint 可以自动给项目内文件统一风格．Physics Learning Wiki 现在启用的配置文件托管在 .remarkrc．

    • LINT-1：不要使用如 <h1> 或者 # 标题 的一级标题．

    图解

    以下用物理写作场景说明排版判断；配图与否由教学任务决定，不使用无关的算法截图作通用范例．

    例 1

    复杂等式用显示公式，并在两侧留空行；标题用可检索的中文对象名，公式留在正文．例如标题写「动能定理」，不直接用整条等式作标题．

    例 2

    同一推导的连续等号可用 aligned 对齐．决定性投影、近似与变量替换仍需要文字解释，不能用对齐代替论证．

    例 3

    代码中的数组索引用行内代码 position[i]；数学分量写成 𝑥𝑖xix_i．来源用脚注说明，并在文末列出可复查的资料．

    例 4

    乘法使用 ××* 或 ⋅⋅*；星号只在已定义的特殊运算中使用．段落写清物理关系，操作步骤可用有序列表，不让短语堆叠取代解释．

    例 5

    几何图与正文统一角度、正方向、源点和场点．替代文字应描述学习所需关系；若图只起装饰作用，可省略．

    例 6

    下标过多时可改用清楚定义的函数或辅助变量．例如先定义源到场点的距离，再写场强投影，避免把全部坐标表达式挤进多层下标．

    例 7

    题目及作答条件留在可见正文；核对答案可折叠，首次方法示范与必要推导则默认可读．具体语义见 信息框规范．

    例 8

    文末的来源应支持对应命题，数据表给出单位与条件．页面呈现检查和来源核验是不同工作，二者都要诚实记录范围．
