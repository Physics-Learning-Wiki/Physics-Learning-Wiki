## 按改动风险选择流程

| 改动   | 最小必要工作                                    |
| ---- | ----------------------------------------- |
| 小勘误  | 原位置、正确依据、最小修正、相关引用或题目的影响                  |
| 教学改写 | 目标读者与任务、保留做法、替换范围、科学条件、需删除或合并的重复段落        |
| 结构迁移 | 在教学改写基础上，检查目录、稳定 ID、锚点、概念、题集与路线，明确迁移及回退方法 |

先排科学错误和关键条件缺失，再检查教学主线，最后调整表达与排版．审阅可以得出「保留原文」；相邻页、图与题目只在实际受影响时修改．写作标准见 [内容编写指引](./writing.md)，具体取舍见 [教学示例](./teaching-examples.md)．

## 用证据形成审稿意见

每项重要发现说明「文件/小节—原文证据—可能困难—成因判断—最小有效建议」．区分科学错误、既有规范执行偏差、规范冲突和待试验的教学安排．主动寻找优点与能反驳初步印象的证据．

可以用「缺失或误导」「存在但未服务任务」「基本可用」「连贯且支持迁移」讨论；未读或未测试写「未观察」，无关项写「不适用」．不计算总分，不让文风优点抵消科学错误，也不按标题、字数或配图数量评分．读者可能遇到的困难是编辑判断，只有实际试读才能形成读者反馈证据．

表达审查关注句段功能：谁变化、固定什么、这一步为何出现、是否重复已有解释．不得凭某个词或句式识别 AI 作者，不建立「AI 常用词」拒稿名单，也不为自然度强加故事、反问或口语．

## 科学核验

对定义、约定、事实、模型假设、推导、近似和类比分别选择依据．重新推导关键关系，检查系统、参考系、变量与固定量、方向、初末态、量纲、分支、极限和数值；尤其注意可能为零的除数、偏导与全导数、显含时间项及重复计算力或能量．

单位定义、数据和历史陈述访问原始或权威来源，说明条件与实际阅读范围．教学假设的数字不能伪装成测量数据；类比不能替代证明．数值工具核对一个模型不等于一般证明，公式渲染成功也不等于物理正确．不能访问或核实的事项明确记录．

## 概念注册与关联检查

正文在第一次有教学意义地需要某个概念时，可以显式引用：

```markdown
由牛顿第二定律，我们得到一个[微分方程](concept:differential-equation)．
```

作者选择引用位置与显示文字，构建系统负责解释和正文入口．同一概念后续重复出现通常保持普通文本，不自动标注关键词．段落、列表、表格和信息框支持引用；首版不支持标题或图片中的引用，代码和公式中的语法示例保持原样．引用文字可以使用符合语境的别名，不必与主名完全相同．

构建后，正文概念链接在便签可用时点击展开解释，并提供「阅读完整内容」入口；无 JavaScript、浏览器不支持或资源加载失败时直接跳转．GitHub 源码预览不能直接打开 `concept:` 链接，请使用本地构建或站点预览检查．

页面可在现有 frontmatter 中声明直接先修：

```yaml
prerequisites:
  - derivative
  - differential-equation
```

构建按作者顺序生成「本页需要」，点击直接进入学习页面．不自动推导依赖，也不要求正文引用都列为先修．需要掌握到什么程度，应在导读中说明．未声明时不显示先修区域．

概念维护在仓库根目录的 `data/concepts.yml`，最小条目如下：

```yaml
version: 1
concepts:
  differential-equation:
    name: 微分方程
    english: Differential equation
    summary: 将未知函数及其导数联系起来的方程．
    target: math/differential-equations/ode-intro.md
```

ID 使用小写英文字母、数字和连接符，以字母开头；命名应稳定，不随页面改名而修改．`name`、`summary`、`target` 必填，`english` 和字符串列表 `aliases` 可选．`target` 相对于 `docs/`，可以带 `#anchor`．别名只用于显示与审校，不触发自动匹配．短释义建议一至两句，说明必要的适用条件；首版按纯文本输出，不解析 Markdown、HTML 或公式．详细公式和推导保留在正文中．

已经迁移到注册表的术语，在术语表相应拼音分组中使用独立标记：

```html
<!-- plw:glossary-entry differential-equation -->
```

构建从注册表生成该条目的名称、英文名、别名、释义和直接正文链接，不回写源文件．修改短释义应编辑注册表，不要同时保留手写的重复条目；尚未迁移的术语继续按原方式维护．

本地运行 `uv run mkdocs build --clean` 检查引用．重复 ID、未知 ID、缺少必填字段、无效目标文件或锚点、重复先修以及不支持的引用位置都会使构建失败，即使全站未启用严格模式．根据错误中的源页面、概念 ID 和目标修正内容；页面搬迁时更新注册表中的 `target`．

页面目标与题集关联按实际需求设置；普通页面不强制新增 `page_id`、学习目标或 assessment．已有页面契约中，目标 ID、标题与显式锚点必须有效，目标 ID 须全局唯一．锚点应落到实际解释该能力的位置，而不只是页首目标声明；移动锚点时保留 ID，并确认没有重复．题目回学链接须实际点回检查．

改概念定义时核对摘要和题目解释；改主线时核对上级导读与路线．`data/concepts.yml` 与 `question-bank/taxonomy/concepts/` 独立维护，不能互相猜测 ID．

## AI 辅助与人工责任

AI 可以辅助组织、写初稿、复算和提出候选意见，但不能虚构资料访问、实验数据、读者试读或独立专家审阅．报告实际检查范围，科学和来源不确定项交给真实维护者判断．「可试读」「示范候选」只能作为编辑讨论用语，不新增生产状态．

正式题库要求当前版本及内容指纹对应的物理、教学、版权三维真实人工签署，详见 [题库审核规范](https://github.com/Physics-Learning-Wiki/Physics-Learning-Wiki/blob/main/question-bank/REVIEWING.md)．AI 不调用 `attest` 或批量 `apply`，不代填 reviewer、日期或指纹，不降级已发布题来绕过门禁．一般知识页也不得伪造人工审核记录．

## 验证与呈现

按变更选择现有检查入口；只改解释不要求执行无关前端全套测试：

```bash
uv run python scripts/check-format.py <修改的文件或目录>
uv run python scripts/check-terminology.py <修改的文件或目录>
uv run python -m scripts.question_bank validate
uv run python -m scripts.question_bank math-audit
uv run mkdocs build --clean
```

发布前用 `corepack yarn site:build` 检查生产处理、SEO 与资源预算；涉及实现时再按对应模块运行类型、单元及交互测试．失败要记录原因和是否原已存在，不能删检查或降低门禁．不要把只检查暂存差异的命令空跑成功当作文件已通过．

在最终页面检查桌面与窄屏的主线可见性、公式、图表及局部滚动，实际使用键盘操作折叠答案和概念链接．检查图片替代文字和回学目标，必要时检查无脚本普通跳转．顺读必要的前后页；尚未执行的检查明确写出．

## 最小修改与审稿记录

记录可作为 PR 短段落；小勘误无需填满所有栏目：

```text
对象、版本与实际审读范围：
目标读者与任务：
原文优点与本次修改范围：
科学核验、依据与尚未确认项：
教学发现及替换／合并范围：
关联影响（ID、锚点、概念、路线、题集、图源）：
实际执行的检查、结果与未执行项：
待解决的阻断问题与后续任务：
真实人工审核者及日期：由实际审核者填写，AI 留空．
```

科学勘误与叙事实验应能分别审阅和回退．真实读者试读关注解释、方法选择与新情境应用；喜欢程度、停留时间和收藏不能单独证明学会．未试读的改写只描述编辑目标与已完成的核查，不宣称已提升学习效果．
